## Context

- **D3 — `hooks/sccgo-hooks.cjs`**: off regex → `/[$@/]sccgo(-partial|-lite)?\s+off\b/i`; activation regex → `/[$@/]sccgo(-partial|-lite)?\b/i`; mode derivation normalizes the capture then compares — `const cap = (m[1] || "").toLowerCase(); const mode = cap === "-lite" ? "lite" : cap ? "partial" : "full";` (case-proof: `$SCCGO-LITE` must arm lite, not silently partial); the activation seed message's two-arm ternary becomes a 3-key note map (full / partial / lite; the lite value pins its own body — "pre-seeded with the lite battery (five skills) → move into the plan's SDD workspace as USED_SKILLS.json, fill `plan`; impeccable/hallmark per the activation rule" — mirroring the full note's shape); the activation **banner** mirrors partial's mode-suffixed shape — `CONTRACT ACTIVE (lite battery)` traces to this line (the fixture literal must not be guessed); `seedLedger()` → `seedLedger(mode)` (full → CATALOG−SEED_EXCLUDE; lite → LITE_CATALOG); `toolUse` first arm widens `full` → `full || lite` (list and count picked by mode, no new branch block) AND the second arm ("already in flight") widens `state.mode === "full"` → `state.mode !== "partial"` so a lite re-approval keeps its mode label instead of falling into the partial else.
- **D4 — `hooks/sccgo-hooks.test.cjs`**: mirror the existing fixtures — lite activation asserts `CONTRACT ACTIVE (lite battery)`; lite plan approval pre-seeds exactly 5 active skills; `$sccgo-lite off` clears state — and fixture 3 also carries the off-regex regression pin: after activating a full or partial session, `$sccgo off` / `$sccgo-partial off` clears it (the widened `(-partial|-lite)?` group governs the working escape hatch; no transcription slip may kill off for the existing modes); a fourth fixture pins case-insensitive lite activation (`$SCCGO-LITE …` arms lite, not partial); a fifth fixture fires `tool-use` twice on a lite session and asserts the second PostToolUse message is the "already in flight" text, not the partial-else text (that arm has zero coverage today) — **and a seventh pin mirrors it from the full side**: a full session's second `tool-use` asserts the "already in flight" text too (the `=== "lite"` transcription slip passes every other fixture and silently routes full re-approvals into the partial else — fixture 6's partial double-fire does NOT bite that slip); a sixth fixture pins the partial path against the widened dispatch — activate `$sccgo-partial`, fire `tool-use`, assert the partial seed-instruction message AND that no `sccgo-pending-ledger.json` was written (the widening reshapes the branch that routes partial; without this pin a copy-paste slip on the widened predicate would hook-pre-seed a 45-skill ledger into partial sessions).
- **D5 — versions + docs**: `plugins/sccgo/.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` sccgo entry → **0.1.8** (0.1.7 was a bot-only bump never present in this tree); README "Factory modes" paragraph: the count word "ships two skills" → "ships three skills", the enumeration gains the `$sccgo-lite` clause, AND the Claude Code qualification list gains `sccgo:sccgo-lite`.
- **D6 — ship**: `git status` first; commit only the named files (message via Write tool + `git commit -F`, `git -C` forms — the Mimosa hook pattern-matches heredoc message text); push `origin/main`.

## Rulings I made

- 电池选型：`do + oops + ro` + `concurrency + database`（头脑风暴提问未获回复，按最佳判断裁定——系统缺陷三联 + 持久化/交错镜头，贴合本机 Go 缺陷史）。
- Lite 电池**固定、总是播种**，不按表面需求——这是 lite 与 partial 的分界。
- 工艺镜头沿用 partial 的激活规则（仅 UI 计划）；ponytail 每轮叠加（优先），不变。
- Lite 在批准时**机械预播种**（与 full 平行）——lite 的意义就是确定性的小清单。
- 协议文本**复制而非去重**（read-one-SKILL.md 派发契约；仓库先例）——文件内标注上限：第四模式出现时改共享协议文档。
- 探针表裁剪到电池自身镜头——子集技能携带死镜头行，每轮都费 token。
